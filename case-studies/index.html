01 / AI RESEARCH SYSTEMS

EvidencePilot

PythonStreamlitGeminiKeyword + semantic retrievalHosted demo

Problem. Document Q&A can produce fluent answers without making it easy to inspect the underlying evidence. For research work, that makes it difficult to tell which claims are supported and where retrieval is weak.

Solution. EvidencePilot combines PDF-based research, passage retrieval, source-grounded answers, answer and research audits, human review and a retrieval evaluation lab in one workspace.

PDF uploadText extractionKeyword / semantic retrievalEvidence reviewGrounded answerClaim audit

Engineering decisions

  • Keep retrieved passages inspectable so users can examine the material used to support an answer.
  • Separate answer generation from auditing and human review rather than treating a model response as a final verdict.
  • Include retrieval metrics such as Hit@K, Page Recall@K and MRR@K against a defined set of relevant pages.

Trade-offs and limitations

Retrieval metrics describe performance on the supplied evaluation set, not general research quality. AI-generated answers can still omit context or misinterpret evidence. Scanned PDFs may need OCR; the documented workflow is focused on text-based PDFs.

The design principle: a useful answer should make its evidence easier to inspect, not harder.

02 / FULL-STACK · APPLIED AI

TrackCake

Astro 5TypeScriptSupabase Auth + PostgreSQLGroq / Gemini / OpenRouterVercel

Problem. Food logging can be cumbersome, and AI estimates are only useful when people can review and correct them before saving. A diary also needs reliable persistence and clear user-data boundaries.

Solution. TrackCake supports manual entry, natural-language estimates and photo-based recognition. Users can edit suggested foods, portions, calories and macros before saving. It includes provider/model selection, a diary timeline and optional account-backed storage.

Manual / text / photoAstro UIServer APILLM providerReview & editLocal / Supabase

Engineering decisions

  • Keep provider credentials on server routes; the model catalogue endpoint returns model identifiers and status, not secret values.
  • Keep AI suggestions editable and separate from the final diary write.
  • Support local browser storage and optional Supabase Auth with user-scoped Row Level Security for cloud persistence.
  • Use an automatic provider fallback path while allowing a user to select a specific configured provider/model.

Trade-offs and limitations

Nutrition estimates and image portion recognition can be wrong; they are not medical advice. Provider catalogues, access and rate limits change. Anonymous browser sessions are not a substitute for a recoverable account when moving between devices. Static-only hosting cannot run the server API routes.

AI assists the entry process; the user stays in control of what is saved to the diary.

03 / BACKEND · DATA CORRECTNESS

Hourly

Next.js 16React 19TypeScriptSupabasePostgreSQL

Problem. Time tracking looks simple until sessions cross midnight, breaks are edited, or local daylight-saving rules change. A timer that only stores a running counter is difficult to reconcile and audit.

Solution. Hourly stores source punch and break timestamps, then derives working time from those records. The browser timer is a display; it does not write a database update every second.

User / AuthNext.js UIServer actionsPostgreSQL timestampsShared time rulesReports / CSV

Correctness rule: breaks

  • A completed break shorter than 15 minutes is recorded but counts as paid work.
  • A break of 15 minutes or longer is deducted in full.
  • An open break is provisional: it is not deducted before 15 minutes; after that threshold its full elapsed duration is deducted.
  • The same calculation module feeds the dashboard, history, reports and CSV export.

Reliability and security

Database functions use authenticated user identity and server/database timestamps. Row Level Security scopes records to their owner. Locking and partial unique indexes protect active-session and open-break transitions. Unit tests cover 14:59, 15:00 and 15:01 break boundaries, multiple breaks, midnight/week boundaries and daylight-saving weeks.

Trade-offs

Database integration checks require a configured Supabase project; the README distinguishes these from local unit tests and the manual authenticated workflow checklist.

04 / AI AGENTS · MCP

Maplewood AI Front Desk

Python 3.11+FastMCPPytestStructured workflowsPrototype

Problem. A clinic inbox agent must not jump directly from natural-language input to sensitive actions. Identity checks, escalation rules and explicit tool boundaries matter more than conversational polish.

Solution. This prototype processes a synthetic family-clinic inbox, applies a deterministic emergency gate and verification checks, exposes clinic operations through MCP tools and produces structured outputs with an audit trail.

Inbox messageTriage / policyIdentity verificationMCP toolsSafety validationStructured result

Engineering decisions

  • Run deterministic emergency checks before ordinary workflow actions.
  • Require a process-local verification token before chart-sensitive tools.
  • Keep tool operations separate from action policy and only mutate appointments after verification and slot checks.
  • Use an offline deterministic evaluator by default; optional LLM classification supplies hints, not executable policy decisions.

Evaluation boundary

The supplied evaluation uses 40 synthetic messages. The README reports a 100% in-sample emergency recall and action/intent exact match, but explicitly notes that the sample is small and tuned during implementation. Two supplied labels conflict with the written privacy contract; the implementation follows the privacy contract and returns null for unverified patient identity. The MCP stdio handshake was not live-smoke-tested in the documented build environment.

Prototype only. Not a medical device or production clinical workflow. No real patient records or clinic-system integration.

05 / FULL-STACK · OPERATIONS

ClashCommand

Next.js 16React 19TypeScriptPostgreSQLDrizzleVitest / Playwright

Problem. Clan, player and war operations can become fragmented across saved records and external game data. The application needs a domain model that keeps these entities independently queryable.

Solution. ClashCommand provides an authenticated dashboard for saved clans, player profiles and war history, with role-aware admin operations, API routes and a synchronization script for refreshing data from the Clash of Clans API.

BrowserNext.js App RouterAuth / role checksAPI + DrizzlePostgreSQL

Domain and integration decisions

  • Model users, roles, clans, memberships, players, seasons, wars, attacks, defenses and activity logs separately.
  • Use Zod for validation and NextAuth credentials/JWT sessions for authentication.
  • Keep external API synchronization in a trusted local script rather than on every dashboard page request.
  • Keep database and game API credentials server-side.

Trade-offs

The sync process is an explicit operational step. Production deployment requires a PostgreSQL database and configured authentication secrets. Database migrations should be reviewed before applying to production.

06 / AI · DOCUMENT INTELLIGENCE

ProfBot

PythonStreamlit + CLIBM25-style retrievalGeminiSupabaseArgon2id

Problem. Document question answering needs more than an LLM call. Users need a clear source path, private storage, sensible abstention and a way to avoid spending model requests on irrelevant questions.

Solution. ProfBot combines a CLI and Streamlit interface over shared extraction, chunking, retrieval and answer services. It supports PDF, TXT and pasted text, selected-document context and source-aware citations.

PDF / TXT / textPage-aware chunksLocal BM25Relevance thresholdGemini answerValidated citations

Engineering decisions

  • Run document extraction and indexing locally; upload/indexing does not call Gemini.
  • Abstain before model invocation when no chunk meets the relevance floor.
  • Map returned source IDs to application-owned chunk metadata and discard model-invented labels.
  • Hash passwords with Argon2id and store private files and conversations with owner-scoped Supabase persistence and database-backed daily quotas.

Trade-offs and limitations

The project is an interview-ready demo, not an audited identity or document-security product. Do not upload confidential or regulated documents without reviewing service terms and privacy requirements. Retrieval is lexical BM25-style ranking, not a paid embedding or vector search pipeline.
